# Реальная география в TrussLab 9.3 — импорт OSM и Copernicus

**Что работает:** игра умеет принимать локальный `TrussLabGeoPack` с цифровыми береговыми контурами OSM (`natural=coastline`) и высотами Copernicus DEM GLO-30. После загрузки 2D, 3D и система секторной загрузки используют единую модель. Названия источников и их точность отображаются в интерфейсе.

**Что не встроено:** сами настоящие OSM/GLO-30 файлы пока отсутствуют в архиве. Из среды подготовки получить их напрямую не удалось. Файл со встроенным контуром GSHHG остаётся резервом для полностью автономной игры. Не выдавайте старые художественные контуры за настоящие OSM.

## Быстро подготовить данные на Windows

1. Установить **Python 3.11+** с https://www.python.org/downloads/ и разрешить `py` в PATH.
2. В распакованной папке проекта запустить **`prepare_geodata_windows.cmd`** с интернетом. Первый запуск установит `numpy`, `scipy`, `rasterio`, `Pillow`, а затем скачает OSM coastline через Overpass и Copernicus DSM tile N45E036 с публичного AWS S3.
3. Дождаться создания `data/kerch_geopack.json` и `data/kerch_geopack.preview.png`. **Посмотреть PNG** и убедиться, что берега узнаваемы; автоматическая классификация направленных линий OSM может ошибиться на разорванных участках.
4. Открыть `TrussLab_Architect_9_3_Standalone.html`, перейти к Крымскому мосту → 3D и нажать **«📦 OSM + DEM»**. Выбрать `data/kerch_geopack.json`.
5. Переключатель «Берег: OSM» меняет источник берега; «⛰ DEM: вкл» включает или выключает настоящие импортированные высоты.

**Без интернета:** если файлы уже получены в QGIS / Copernicus Data Space, можно выполнить:

```
py -3 -m pip install -r tools/requirements-geo.txt
py -3 tools/prepare_geodata.py --osm-json downloaded_coastline.json --dem-tif downloaded_GLO30.tif --output data/kerch_geopack.json
```

`--osm-json` принимает JSON ответа Overpass с `geometry` либо GeoJSON из линий, **не** административные полигоны. Для WGS84 полигонов суши можно также использовать кнопку «GIS GeoJSON» (из версии 9.0). `--dem-tif` принимает GeoTIFF с метаданными системы координат, который автоматически преобразуется к игровой сетке; рекомендуется оригинальный Copernicus GLO-30 COG.

## Масштаб и ограничения

- Публичный Copernicus GLO-30 — это **цифровая модель поверхности (DSM)**, а не почвенно-геотехническая или гидрографическая съёмка. Шаг исходной сетки около 30 метров; в игре данные перевыбираются на сетку 512×512 с размером ячейки около 65 м.
- Привязка по WGS84 в текущей игре остаётся **предварительной**, по одной известной координате и условному направлению главной оси. Геометрию мостового перехода нельзя считать топографически или инженерно достоверной даже после импорта.
- Высоты в 3D отображаются с **вертикальным преувеличением**: 8 м на игровую вертикальную единицу. Дорога и основание моста остаются условной моделью.
- Берега из OSM строятся как ближайшая сторона линий `natural=coastline`: земля слева от направления OSM-ways. Это корректный смысл OSM, но **автоматическая растеризация открытых цепочек может создавать локальные ошибки**. Не использовать для навигации или проектирования.
- Снятие морского дна и настоящих глубин в Copernicus GLO-30 **нет**; поверхность моря в игре художественная.
- Внешние данные можно экспортировать вместе с JSON-проектом. `localStorage` имеет ограничение размера — при ошибке сохранения лучше использовать экспорт JSON.

### Исправление 9.3.1: тайм-аут Overpass
Если все серверы Overpass не отвечают, загрузчик теперь сообщает предупреждение и продолжает загрузку Copernicus DEM. Полученный JSON в таком случае содержит **только DEM**, а береговая линия остаётся из резервной карты игры. Чтобы добавить OSM позже, повторите команду `py -3 tools/prepare_geodata.py --download --output data/kerch_geopack.json` либо передайте локальный GeoJSON через `--osm-json`. Успешное завершение не означает, что оба источника присутствуют: проверяйте строку «Слои пакета».


## Исправление 9.3.2: перегруженные серверы Overpass

Лог с сообщением `The read operation timed out` означает **сетевой тайм-аут Overpass**, а не проблему с Python 3.14 или установкой GIS-библиотек. Утилита теперь не завершает работу после сбоя OSM, а продолжает скачивать Copernicus DEM.

- Обычный запуск: `prepare_geodata_windows.cmd` — пробует 3 Overpass-сервера по 25 с каждый, затем скачивает DEM.
- Быстрый запуск: `prepare_dem_only_windows.cmd` — сразу скачивает DEM, не обращается к Overpass.
- Позже можно дополнить готовый файл OSM, не теряя высоты: `py -3 tools\prepare_geodata.py --download --osm-only --output data\kerch_geopack.json`.
- Если есть собственный GeoJSON из OSM, используйте: `py -3 tools\prepare_geodata.py --osm-json путь_к_файлу.geojson --output data\kerch_geopack.json`.

Утилита пишет **«Слои пакета: OSM + DEM»** или **«Слои пакета: без OSM + DEM»**. Второй результат — корректный DEM-пакет, но точной береговой маски OSM в нём нет: пока используется уже встроенный береговой слой TrussLab.

При повторном запуске уже полученные слои GeoPack сохраняются, а новые добавляются. Оригинальный HTML и игровой движок не менялись, исправлен только GIS-загрузчик.
