# TrussLab 9.4.1 — исправление контроля «Берег × трасса»

## Причина вывода «0 пересеч., 0% по суше»

Проверка в 9.4 не привязывает мост к OSM. Она только опрашивает маску суши под текущими осями. Если весь условный мост проходит по воде, корректно получатся **0% суши и 0 пересечений**, даже когда в GeoPack всего 35% территории является сушей. Предыдущий вывод не различал полностью водный маршрут и выход за пределы карты. Географическая система WGS84 по-прежнему основана на одном якоре и приблизительном направлении оси.

## Исправлено в 9.4.1

- Проверка показывает долю суши всей маски, количество проверенных пикселей, статус обеих осей, расстояние от концов линий до ближайшей суши (в км по приблизительному масштабу игры). Вывод отчётливо отличает «вся ось в воде» от «вне охвата GeoPack».
- По нажатию **«◎ Берег × трасса»** автоматически открывается **2D → План местности** и показывает цветные точки: **зелёные = суша, красные = вода, серые = вне маски**. Жёлтые точки означают найденное пересечение. Положение геометрии при этом **не меняется**.
- В **«✥ Править трассу»** теперь доступны *включая крайние* контрольные точки Керчи и Тамани, поперечное смещение до ±80 игровых единиц. Все правки остаются редактируемыми, сохраняются в проекте и могут быть отменены (Ctrl+Z). **Перетаскивание не означает точную геодезическую привязку.**
- Реальные данные Copernicus DEM и береговая OSM-маска не переписываются.

## Быстрый запуск

1. Откройте `TrussLab_Architect_9_4_1_Standalone.html` или автономный HTML из ссылки.
2. В 3D нажмите **📦 OSM + DEM** и откройте свой файл `E:\TrussLab_Architect_9_3\data\kerch_geopack.json` (результат успешного импорта OSM и Copernicus). Ничего заново скачивать не нужно.
3. Нажмите **◎ Берег × трасса**. Откроется план с подсветкой дороги и двухпутной железной дороги. При полностью красной трассе берег может быть правильным, но сам маршрут ещё не совпадает с ним.
4. Для ручного эксперимента включите **✥ Править трассу**, двигайте в том числе первую и последнюю точку. Старайтесь не использовать подгонку для утверждения точности 1:1. При наличии реальных линий используйте **🧭 Ось GeoJSON**.

## Офлайн PNG-диагностика точного пользовательского GeoPack

В полном исходном ZIP есть `diagnose_route_windows.cmd` и `tools/diagnose_route_geopack.py`. Скрипт **не изменяет GeoPack и не обращается к интернету**. Он рисует отдельный PNG, на котором видны настоящая береговая маска и предполагаемая ось дороги/ж/д.

Из папки новой версии запустите:

```powershell
py -3 .\tools\diagnose_route_geopack.py --geopack "E:\TrussLab_Architect_9_3\data\kerch_geopack.json"
```

Появятся файлы рядом с GeoPack:

- `kerch_route_alignment.png` — наложение условных осей на береговую маску;
- `kerch_route_alignment.txt` — проценты, пересечения, близость суши и примерные координаты концов.

Если вы изменили трассу и экспортировали линии через **↓ Ось GeoJSON**, можно добавить `--route "путь_к_файлу.geojson"`, чтобы использовать их при анализе (без последующей правки самой маски).

**Для исправления точной географической привязки** пришлите PNG из этой утилиты или сам файл `kerch_geopack.json`. По сообщению «35% суши» невозможно определить, где именно находится суша относительно моста. Само по себе наличие начальной и конечной точки на суше не доказывает соответствие реальному сооружению.
